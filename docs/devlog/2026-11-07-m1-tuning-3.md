# 2026-11-07 — 조정 3: 창 3연속 찌르기, 빠른 부활, 헬퍼 브리핑, 보호막·미확인 제거

## 결정 (플레이 피드백 + 스토리 논의)

| 결정 | 이유 |
|---|---|
| 창 찌르기 → **3연속, 세 번째 지연** | 한 번 찌르고 끝나 아쉬움. 박자 읽기 연습 |
| **보호막 제거** | 빠른 부활이 실수에 대한 보험 역할을 대신함. 한 방 사망 규칙이 깔끔해짐 |
| **빠른 부활** (카타나 제로식) | 죽으면 직전 패턴 시작 전으로 바로 되감기 + 짧은 사망 원인 메시지. 같은 구간 5번째 → 사망 지도 → 체크포인트 |
| 보스 체력도 되감기 | 한 패턴을 확실히 넘겨야 하는 긴장감 (5번 제한이 있어 지나치게 가혹하지 않음) |
| **미확인 패턴 폐기** | 튜토리얼에서 많이 죽게 하려던 장치였으나 헬퍼 브리핑 + 빠른 부활로 대체. 놀라는 순간은 "첫 페이즈 패턴에서 헬퍼 지시대로 하다 죽음 = 2막 시작"이 맡음 |
| **헬퍼 브리핑** | 일반·강 패턴은 전투 전에 헬퍼가 무기·패링 가능 여부·파훼법을 안내. 페이즈 패턴은 시작 순간 멈추고 설명 (페이즈 단계) |
| 스토리: 비밀 목적 | 로봇 패턴이 의도와 다르게 바뀌어서, 회사가 원인을 찾으려 테스터를 몰래 투입. 원인 = 해킹당한 헬퍼 → **보스가 헬퍼의 파훼법을 전부 알고 있었다** |

## 구현

| 항목 | 내용 |
|---|---|
| 되감기 | `utils/snapshot.ts`: 모델의 필드를 깊게 복사해 저장·복원 (설정·경계는 그대로 두고, 함수는 복사하지 않음). 보스가 새 패턴(첫 타)을 시작할 때마다 플레이어·보스 상태 저장 |
| 되감기 후 | 전투 판정 기록도 새로 시작 (안 그러면 "이미 맞은 공격"으로 기억해 되감은 공격이 안 맞음), 움직임 기록·히트스톱·입력 초기화, 화면 살짝 번쩍 |
| 재시도 | `run/Revive.ts`: 구간당 5번, 새 체크포인트 저장·재시작·클리어 시 다시 채움. 왼쪽 위 ●●●○○ |
| 헬퍼 브리핑 | `data/helperBriefing.ts` (대사 데이터) + `ui/Briefing.ts` (HTML). 처음 접속 시 표시, 일시정지 메뉴 "패턴 안내"로 다시 보기 |
| 정리 | 보호막(설정·모델·HUD·그리기·판정 이벤트), 관측 기록·`UNKNOWN`·`PATTERN LOGGED`·사망 지도의 패턴 목록 제거 |

## AI 사용

- **검증 장치의 빈틈 1건 발견·보강**: 스냅샷의 깊은 복사를 얕은 복사로 망가뜨려도 테스트가 통과. 확인해 보니 지금 모델들은 안쪽 객체를 항상 새로 만들어 넣어서(제자리 수정이 없음) 얕은 복사로도 동작은 같음. 하지만 나중에 제자리 수정이 생기면 되감기가 조용히 깨질 수 있어, 복사 도구 자체를 직접 검사하는 테스트 추가 → 이제 둘 다 잡힘
- 화면 확인: 브리핑(5장 카드가 540 높이 안에 들어오는지 측정), 결과 화면 → headless Chrome 스크린샷
