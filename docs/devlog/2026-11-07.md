## 2. M0 세팅

- 목표: 개발 환경과 저장소 뼈대
- AI 사용: 프로젝트 설정 파일, 확인용 씬(사각형 WASD 이동), 테스트 예제, 배포 워크플로 작성 요청 → 사용
- 원리 메모
  - 게임 루프: Phaser가 매 프레임 `update(time, delta)`를 호출한다.
  - 프레임 독립 이동: 속도 × (delta / 1000) → 프레임 속도와 무관하게 같은 속도.
  - 대각선 정규화: 방향 벡터 길이를 1로 맞춰 대각선 이동이 빨라지지 않게 한다.
- 결정: 라이브러리 버전을 미리 적지 않고 설치 시점 최신 안정 버전을 받아 기록한다 (환각 방지).
- 결정: `npm install`은 Windows에서 직접 실행 (원격 리눅스 환경에서 설치하면 일부 빌드 도구가 리눅스용으로 설치될 수 있음).
- 실행 결과 `[검증됨]`
  - `npm test`: 4개 테스트 통과
  - `npm run typecheck`: 오류 없음
  - `npm run dev`: Vite 개발 서버 실행
- 실패 / 배운 점
  - 원격 도구는 `.github` 폴더에 쓸 수 없음 → `_setup/`에 두고 직접 옮김
  - 설치된 버전이 Phaser 4, TypeScript 7, Vite 8, Vitest 5 → AI가 아는 것보다 새 메이저 버전. Phaser 3 방식으로 쓴 코드(`import Phaser from 'phaser'`)는 타입 검사 통과
  - 첫 푸시 실패: GitHub 저장소를 만들기 전에 푸시함 (`git remote add`는 주소를 기록할 뿐, 저장소를 만들지 않음)
  - AI가 파일을 고쳐 썼다고 보고했지만 실제로는 이전 내용이 쓰인 경우가 있었음 → 쓰기 후 실제 파일 내용을 다시 읽어 비교하는 검증 단계 추가
- 저장소 이름: `read-me-game` 유지. 배포 경로는 GitHub Actions의 `GITHUB_REPOSITORY` 값에서 자동으로 읽도록 변경 (이름을 바꿔도 코드 수정 불필요)
  - 첫 배포 실패: 저장소에서 Pages를 켜지 않아 `configure-pages` 단계에서 Not Found → Settings → Pages → Source를 "GitHub Actions"로 지정해 해결
  - Node 20 경고: AI가 추정으로 적은 actions 버전이 구버전 → 릴리스 노트를 검색해 Node 24 버전으로 갱신 (checkout v5, setup-node v5, configure-pages v6, upload-pages-artifact v5, deploy-pages v5)
- 소요 시간: 예상 _h / 실제 _h
