## 결정

| 항목 | 결정 | 이유 |
|---|---|---|
| 보스 생김새 | 검은 육각형 + 흰 삼각형(바라보는 방향) | 내러티브의 "학습하는 기하학적 존재". 플레이어(원)와 한눈에 구별. 3D로 가면 육각기둥 |
| 시각 표현 | 우선 2D로 M1 완료 → 이후 3D(Three.js) 시험판으로 비교 | M1의 질문("학습이 느껴지는가")은 그래픽과 무관. 로직·화면 분리 덕분에 렌더러 교체 비용이 작음 |
| 예고 | 빨간 점선 → 판정 순간 빨간 실선 + 채움. 예고 중 채움이 점점 진해짐 | "빨강 = 위험" 하나만 사용 |
| 패링 불가 표시 | 점선을 이중으로 | 색을 늘리지 않고 구별 |
| 조준 | 예고 시작 순간의 플레이어 위치로 고정, 예고 중 회전 없음 | 예고가 보여준 범위 = 실제 판정 범위 (공정성) |
| 큰 빈틈 | 점프 내려찍기 후 숨 고르기 동안 보스가 회색 | 공격 기회라는 신호 |
| 공격 선택 | 거리 기반 가중 무작위. 사거리 안 공격 우선, 직전 공격 반복 금지 | 학습은 4단계에서 추가 |

## M1-2a' — 첫 플레이 피드백 반영

### 피드백

| 피드백 | 반영 |
|---|---|
| 속도가 마지막 페이즈 수준 | **1막 수치로 조정**: 예고 약 1.5배(0.9~1.5초), 이동 110→80, 회전 5→3. 처음 값은 이후 "막별 배율"로 3막에 되살림 |
| 보스가 계속 다가오기만 함 | **관찰 상태 추가**: 공격 후 0.8~1.6초 동안 노려보기 / 옆으로 돌기, 너무 가까우면 물러남 |
| 보스 크기 | 반지름 30 → 40 (플레이어의 약 3.3배). 공격 범위도 함께 늘림 |
| 일시정지·재시작 | ESC 또는 오른쪽 위 버튼으로 일시정지 메뉴(계속하기 / 처음부터 다시 / 조작법), R로 바로 재시작. 화면 아래 조작법은 메뉴로 이동 |

### 디자인 판단

- **관찰 상태 = 전투 설계의 "탐색 구간".** 플레이어가 먼저 들어갈지, 포션을 마실지 고르는 시간이고, 이후 보스가 학습할 데이터("관찰 중에 항상 포션")도 여기서 생긴다.
- **일시정지 메뉴는 HTML/CSS로 게임 위에 겹침** (계획서의 UI 이원화 원칙).
- **메뉴 클릭이 공격으로 새는 문제 예방:** 클릭 대기열을 `ClickQueue`(순수 클래스)로 분리하고, 재개 시 비움. 일시정지 중 누른 키의 "눌린 순간" 기록도 버림.
- **씬 재시작 시 HTML 버튼 연결을 해제** → 재시작할 때마다 버튼 동작이 중복되지 않게.
