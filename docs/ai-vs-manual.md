## 3. AI가 못한 영역

### 검증 장치가 잡아낸 것 (사람이 보기 전에)


| 날짜 | 사례 | 잡은 장치 |
|---|---|---|
| 11-07 | Phaser 3 방식으로 `fillPoints`에 `{x, y}`를 넘김 → Phaser 4는 `Vector2[]`만 받음 | 실제 Phaser 4 타입 파일로 한 타입 검사 |
| 11-07 | `async` 통합 테스트가 임시 실행기에서 단언 전에 통과로 찍힐 수 있었음 (검증 도구 자체의 허점) | 테스트를 일부러 망가뜨려 실패하는지 확인 → 실행기가 `async`를 거부하도록 보강 |
| 11-07 | 찌르기 돌진이 준비가 끝나는 프레임을 건너뛰어 30이 아니라 27.5만 이동 | 단위 테스트 (정확한 거리 비교) |
| 11-07 | 되감기용 깊은 복사를 얕은 복사로 바꿔도 테스트가 통과 (지금은 동작이 같아서) → 미래의 조용한 버그 가능성 | 일부러 망가뜨리기 → 복사 도구를 직접 검사하는 테스트 추가 |
| 11-08 | 원거리 타의 "근접 판정 없음" 조건을 빼도 테스트가 통과 → 조준선(경기장 끝까지)에 서 있기만 해도 죽는 버그가 숨어 있을 수 있었음 | 일부러 망가뜨리기 → 판정 테스트 추가 |

## 3. AI가 못한 영역

### 사례 기록

| 날짜 | 사례 | 어떻게 발견했나 | 교훈 |
|---|---|---|---|
| 11-07 | actions 버전을 추정으로 적음 → Node 20 경고 | 첫 배포 실행 | 버전은 기억이 아니라 릴리스 노트로 확인 |
| 11-07 | 파일 쓰기 "완료" 보고 후 실제로는 이전 내용이 쓰임 | 쓰기 후 실제 파일을 다시 읽어 비교 | 완료 보고를 믿지 말고 결과를 확인 (현재는 매번 지문 비교) |
| 11-07 | 콤보가 경직을 통째로 건너뛰는 설계. **테스트도 그 동작을 정상으로 검사** | 사람이 직접 플레이해 보고 "캔슬되는 느낌" | 테스트 통과 ≠ 의도가 맞음. 손맛·느낌은 사람이 플레이해야 검증된다 |

### 경향 (지금까지)

- AI는 **명세대로 동작하는 코드**는 잘 쓰지만, **명세 자체의 빈틈**(경직을 건너뛰어도 되는가?)은 스스로 의심하지 않는다.
- AI가 테스트까지 작성하면, 코드와 테스트가 **같은 잘못된 가정**을 공유할 수 있다.
